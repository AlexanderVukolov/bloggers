# NSL Bloggers: серверные операции (проект v133, НЕ опубликован)

Базовый адрес существующего API: `https://wmnymdmjiczbmjyztcze.supabase.co/functions/v1/bloggers-api`.

Авторизация: `Authorization: Bearer <Supabase access token>` и публичный `apikey`. Роль берётся из серверной `blogger_access`, для остальных сотрудников — из `blogger_employees`. Заголовок x-nsl-role не даёт полномочий. Служебные таблицы закрыты RLS и отзывом привилегий. Секрет service_role применяется только внутри существующей Edge Function.

## Методы

| Метод | Назначение | Разрешение |
|---|---|---|
| GET /whoami | Профиль, роль, permissions | Активный сотрудник |
| GET, POST /api/access | Настройки полномочий руководителя | owner |
| GET /api/diagnostics | Проблемы, связанные ID, записи реестра | diagnose + read_all |
| GET /api/audit | Последние 200 событий | audit |
| GET /api/work-export | JSON с настоящими ID | export + read_all |
| GET /api/import/status | Статус серверной настройки | Активный сотрудник |
| POST /api/import/preview | Проверка рабочей таблицы | import_preview + read_all |
| POST /api/operations/preview | Предварительный просмотр исправления | По kind |
| POST /api/operations/{id}/commit | Применить сохранённую проверку | По kind |
| POST /api/import/{id}/writeback | Повторить возврат ID после сохранения | import_apply |
| POST /api/operations/bug-report | Черновик описания ошибки | diagnose |

Проверка возвращает `{id,expires_at,changes,blocked,rows?,conflicts?,requiresConfirmation:true}`. Применение: `{"confirm":true}`. Подтверждённая операция исполняется транзакционно, повтор того же ID возвращает сохранённый результат. Срок предварительного просмотра — 30 минут. Проверяется версия каждой строки. Ошибки: 400 неверные поля; 401 сессия; 403 полномочия; 409 конфликт/устаревшая проверка; 503 Google не подключён. Ответ `{error,code,details?}`. Не передавать секреты в параметры.

Пример редактирования:

```json
{"kind":"edit_work","entity":"placement","id":"123","reason":"Исправление по первичной статистике","values":{"actual":0,"clicks":{"clear":true}}}
```

Виды: edit_work, relink (`bloggerId`, для отчёта также `placementId`), merge (`sourceId`,`targetId`,`choices` с source/target по каждому конфликтующему полю), archive (`entity`,`id`,`excluded`, причина), undo (`operationId`), recalculate. Поля: блогер name/display/link/platforms/brand/manager/status/plannedReach/comment; размещение bloggerId/brand/manager/type/sortDate/warmupStart/warmupEnd/guaranteed/actual/clicks/contentLink/statisticsLink/status/decision/cost/packageId. Полный разрешённый перечень — FIELDS в operations-core.mjs.

## Таблица

Читаются только «Блогеры» и «Размещения» указанной в ТЗ таблицы. Максимум 4999 строк данных на лист. Точные заголовки сверяются. Резервный ID обязателен и уникален. Сопоставление по нику не применяется автоматически. Параметр preview `resolutions` содержит ключи вида `blogger:B-...` или `placement:P-...` и выбранный CRM ID; значение NEW подтверждает отдельную новую запись.

Пусто — не менять; 0 — записать ноль; `⟦ОЧИСТИТЬ⟧` — явная очистка. На первом сопоставлении проверенную связь выбирает человек. После импорта baseline используется для трёхсторонней проверки конфликтов. Stories — одна запись, окончание предлагается +4 дня; остальные форматы отдельны. При packageId общий гарант должен стоять только в одной строке пакета; исторические пакеты не угадываются.

Возврат ID: только колонка A, закрепление строки developerMetadata, проверка резервного ID до записи и чтение после. Сбой возврата не откатывает уже сохранённые CRM данные; повторяется только writeback. Защитить A/B от ручного редактирования и проверить поведение сортировок на тестовой таблице до запуска.

## Действия владельца перед включением

1. Создать отдельный сервисный аккаунт Google, включить Google Sheets API. Выдать ему редактора только нужной таблицы. Не выдавать доступ ко всему Google Drive.
2. В Supabase Edge Functions Secrets сохранить `BLOGGERS_GOOGLE_SERVICE_ACCOUNT_JSON`. Не отправлять JSON в чат и не класть в GitHub или ячейки.
3. После завершения тестов применить миграцию. Она сохраняет серверный снимок рабочих таблиц в закрытой схеме nsl_bloggers_private. Файловые объекты Storage этот снимок не копирует.
4. Привязать проверенный профиль Александра к owner, Марии — supervisor с выбранными разрешениями; не назначать владельца через клиент. В рабочей базе это ещё НЕ выполнено.
5. Проверить тестовую таблицу и повторную загрузку. Затем развернуть функцию вместе с operations.mjs и operations-core.mjs; опубликовать клиент, обновить service worker.

## Текущее состояние и ограничения

Это незавершённая ветка. Не применять к рабочей базе. Ещё нужны: удобные формы без JSON, выбор сопоставлений в интерфейсе, отдельный экран управления разрешениями; согласованное обновление версий фактов/периодов/отчётов в старых формах; проверка всех путей архивации и итогов в legacy KPI, ежедневных Stories и пакетах; полноценный пересчёт KPI; отмена импорта; удаление ПД из отчёта разработчику; массовый preview для legacy-редактирования; полный сквозной Google тест, резервирование файлов и браузерная проверка. Отмена после конкурентного изменения проверяется на уровне транзакции, но полный набор сценариев ещё не выполнен. Готовность интеграции не подтверждена.
